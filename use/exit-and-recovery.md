# 退出聪网与故障恢复

退出与恢复不是同一个动作。普通退出优先使用splicing-out或协作close；force close与punish是异常保护路径。任何路径都必须先确认当前钱包、子账户、通道和网络。

## 正常退出

1. 少量资产回到BTC L1：在Channel资产上选择splicing-out，核对目标L1地址、资产、数量和费用。
2. L2个人地址上的资产：先lock回通道；容量不足时由钱包明确询问是否付费扩容。
3. 结束整个通道：使用协作close，并等待关闭交易完成后再创建新通道。
4. 记录L2 deAnchor/通道动作和最终L1交易，在两条网络分别验证。

## 异常保护

- Core Node离线、拒签或双方状态不一致时，先导出安全快照和最新commitment，不要清理本地数据。
- force close会使用最新可执行承诺交易，费用和等待时间可能高于协作关闭。
- 发现已撤销旧commitment上链时，watchtower/钱包应进入punish路径；测试网故障注入接口不得在主网启用。
- 未知网络结果按“可能已经成功”处理，先查reservation、操作日志、L1/L2交易和服务端状态，再决定是否继续。

## 钱包与账户恢复

1. 导入主账户助记词或使用账户恢复包时，应恢复主账户身份和DKVS上的账户管理数据。
2. 导入账户中的非root钱包助记词，只恢复该钱包的链上数据，不应取得原主账户的其他数据。
3. 通道恢复依赖正确子账户、服务端ping快照、commit height和本地安全材料；monitor钱包不恢复通道。
4. 恢复验证完成前，旧设备与新设备不能同时写同一钱包/通道。
5. RGB11恢复分开验证“无RGB资产”和“有RGB资产”；RGB11 L1状态由客户端证明恢复，不从普通Indexer余额伪造。
